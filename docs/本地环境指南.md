## 一、这堆东西是干什么的

一句话：**让你在 Windows 上直接读激光数据、出图、算误差，不需要先折腾 ROS2。**

原来的计划是装 ROS2 + slam_toolbox + rviz，但这台机器上 WSL 被安全策略禁止了
（`wsl.exe` 在程序黑名单里），Docker Desktop 引擎也没启动，所以 Linux 环境暂时建不起来。

好在「从数据入手」这件事 **90% 的工作不需要 ROS2**：

| 你想干的事 | 传统做法（需 ROS2） | 本环境做法（已可用） |
|---|---|---|
| 看 bag 里有什么 | `ros2 bag info` | `01_bag_ledger.py` |
| 画一帧扫描 | rviz2 | `02_plot_scan.py` |
| 统计噪声、帧率 | 手写节点 | `03_scan_stats.py` |
| 导出点集做 ICP | 写 ros2 节点 | `04_extract_scans.py` |
| 算 ATE / 画轨迹对比 | `evo_traj` | `evo`（已装，命令行可直接用） |

所以：**W1 到 W5 的核心工作，现在就能开始。** ROS2 等你需要 rviz2 交互和 slam_toolbox
在线建图时再解决（方案见第六节）。

### 已下载

| 数据集 | 大小 | 位置 | 用途 |
|---|---|---|---|

### 主数据集的实测画像（这些都是跑脚本量出来的，不是抄的）

**意外发现：这个 bag 比你预期的更好用。**

| 项 | 实测值 | 说明 |
|---|---|---|
| 话题数 | 3 个 | `horizontal_laser_2d`、`vertical_laser_2d`、`imu` |
| 消息类型 | `MultiEchoLaserScan` | **不是** `LaserScan`。字段是 `LaserEcho[]` 不是 `float32[]`，直接 `np.asarray(msg.ranges)` 会炸 |
| 水平激光 | 1079 点 · 270° 视场 · 37.5 Hz | 标称 40 Hz，实测 37.52 Hz |
| 角分辨率 | 0.25° | |
| 量程 | 0.02 ~ 60 m | 但场景实际只用到 27 m |
| **IMU** | **250 Hz，478244 条** | ⭐ **有 IMU**，W2 的 lidar-IMU 标定**不用等 M2DGR** |
| 时长 | 31.9 分钟 | 够跑长距离漂移实验 |
| 有效点比例 | 94.8% | |
| 测距噪声 | 2 m 处 1.8 cm → 26 m 处 4.0 cm | 随距离近似线性增长，后端信息矩阵直接用 |
| 帧间隔 | 中位 26.7 ms，**双峰分布** | 另有一簇 34–36 ms，说明约 1/8 的帧有延迟 |

**两个需要记住的坑：**

1. **多回波格式**。`/dists` 里那 6% 的无效点不是噪声，是激光打空或超量程。`tools/slamlib.py` 已经处理了这层差异，你自己写代码时如果直接读 `msg.ranges` 会报错。
2. **帧间隔双峰**。这不是 bug，是真实采集系统的抖动。做时间同步时（W2 第五项），如果假设"固定 26.7 ms"，就会有约 10 ms 的系统性偏差累积。

## 六、ROS2 环境怎么办（现在建不起来，两个方案）

**现状**：`wsl.exe` 被安全策略拦截（安全中心 → 命令安全 → 程序黑名单），
Docker Desktop 装了但引擎未启动（它依赖 WSL2 后端）。

### 方案 A：解除 WSL 限制，走 WSL2（推荐）

1. 打开「安全中心 → 命令安全 → 程序黑名单」，把 `wsl.exe` 移除
2. 管理员 PowerShell 执行 `wsl --install -d Ubuntu-22.04`，重启
3. 进 Ubuntu 后：

```bash
sudo apt update && sudo apt install -y ros-humble-desktop ros-humble-slam-toolbox \
     ros-humble-nav2-bringup ros-humble-rosbag2*
```

4. GUI（rviz2）靠 WSLg 自动显示，Windows 11 免配置。

**注意**：`D:\slam` 在 WSL 里是 `/mnt/d/slam`，可以直接读写，数据不用搬。
但 bag 回放建议拷到 WSL 自己的文件系统（`~/slam`）里，`/mnt/d` 上 I/O 慢，会掉帧。

### 方案 B：不用 ROS2，全程 Python（当前路线）

需要看 3D 点云时装 **CloudCompare**（免费，比 rviz 顺手）：
https://www.cloudcompare.org/

在线建图真需要时，再回方案 A。**不要把时间花在 Windows 原生编译 ROS2 上，那是坑。**

## 八、YDLIDAR X3 实物雷达（E:\工作\激光雷达）

### 8.1 澄清一件事：那里没有 ROS2

`E:\工作\激光雷达\ROS2-源码\源码\` 里是 4 个 **tar.xz 源码包**，已经解压到
`D:\slam\code\opensource\`（690 个文件 / 114 MB）：

| 包 | 内容 | 能干什么 |
|---|---|---|
| `YDLidar-SDK-master` | SDK 源码 + **3 份官方协议 PDF** | 查协议细节，验证你手册里那两个坑 |
| `ydlidar_ros2_driver-master` | ROS2 驱动包（含 `params/ydlidar_x3.yaml`） | 需要 ROS2 才能 `colcon build` |
| `yahboomcar_ws_src` | 亚博激光应用包 | `laser_warning` / `laser_avoidance` / `laser_tracker` 三个算法范例 |
| `ydlidar_ws_src` | **完整 ROS2 工作空间，13 个包** | 含 `slam_gmapping`、`yahboomcar_nav`、`yahboomcar_laser`、`laser_filter` |

**这些是源码，不是 ROS2 运行时。** 没有 ROS2 环境时 `colcon build` 跑不起来，
但作为**代码读物**现在就能看，等 WSL 通了直接编译。

### 8.2 一个必须注意的参数不一致

`ydlidar_x3.yaml` 是亚博的默认值，和你这台实测对不上：

| 参数 | yaml 里写的 | 你实测的 | 后果 |
|---|---|---|---|
| `frequency` | 10.0 | **8.3 Hz** | 时间戳间隔算错，标定时出系统性偏差 |
| `range_max` | 64.0 | **约 8 m**（室内 3–5 m） | 会把超量程点当有效点，噪声爆炸 |
| `range_min` | 0.01 | **0.12 m** | 近处虚假回波 |
| `port` | `/dev/ydlidar` | COM7（Windows） | udev 别名，WSL 里要重配 |

编译后第一次跑之前，先按实测值改这四个。

### 8.4 下一步：录一段真正能用的序列

雷达现在没插（COM7 已被蓝牙占用）。插上后确认是 CH340（VID `1A86:7523`），然后：

```bash
# 先探口确认活着
python "E:/工作/激光雷达/tools/ydlidar_raw.py" --list
python "E:/工作/激光雷达/tools/ydlidar_raw.py" --port COM7 --probe

# 录 300 帧（约 36 秒）到 D:\slam
mkdir -p D:/slam/datasets/x3
python "E:/工作/激光雷达/tools/ydlidar_raw.py" --port COM7 --frames 300 \
       --save "D:/slam/datasets/x3/run01.csv"
```

**录制要求**（这几条决定数据能不能用来建图）：

1. **放地上，不要放桌上**。手持 20–30 cm 高度，周围 2–4 m 内有墙或家具。
2. **必须带回环**：走一个闭合的圈，最后回到起点朝同一方向。没有回环就没法测回环模块。
3. **慢速平移 + 缓慢旋转**，别猛转。X3 是 8.3 Hz，转快了帧间重叠不够，匹配会失败。
4. **录两段**：一段安静环境（基线），一段有人走动（动态干扰对比）。
5. 每段录完立刻用 `05_x3_analyze.py` 检查角度覆盖有没有低于 80%。

## 九、几条纪律

1. **不要删 `env`**。重装一次要十几分钟，而且这机器上清华源不通，得走官方源慢慢下。
2. **不要一上来下 80 GB 的 KITTI 点云**。493 MB 这个 2D bag 够你练到 W7。
3. **每周必须有一个文件产出**。产出不是笔记，是 `docs/` 下的图或表。
4. **数据先跑通再谈算法**。`01` 号脚本跑不出结果，说明环境有问题，先修环境。
